# MagicCode Super-Resolution（MagicSR）用户使用说明书

版本：v2.2.0（`mc_nscaler_version()`）
适用：Native SDK
平台：Android（Vulkan / OpenGLES）、iOS / macOS（Metal）、Windows（Vulkan / Direct3D 11 / OpenGL 4.3）、CPU（x86 / NEON，仅空域）

English: [`User_Guide.md`](User_Guide.md)

头文件：`interface/mc_interface.h`

---

## 1. 产品简介

MagicSR 把调用方提供的图像放大，并写入调用方提供的输出。空域模式每帧只要一张彩色图。时域模式还要深度、运动向量、抖动和相机参数。

公开接口只有这一套：

| 调用 | 作用 |
|------|------|
| `mc_nscaler_control(..., MC_NSCALER_CMD_SET_PARAM, &ctrl, NULL)` | `*handle` 为 NULL 时用 `ctrl_param_t` 创建句柄。之后的调用只更新允许修改的设置。 |
| `mc_nscaler_enable(&handle, &in_frame, &out_frame)` | 处理一帧。 |
| `mc_nscaler_control(..., MC_NSCALER_CMD_QUERY_STATUS, NULL, &status)` | 读取尺寸、模式、`gpu_time` 和 `error_code`。 |
| `mc_nscaler_disable(handle)` | 释放句柄。 |
| `mc_nscaler_version()` | 静态版本字符串，当前为 `v2.2.0`。 |

每个结构体先清零，再填要用的字段。GPU 纹理和 CPU 缓冲都由调用方持有。库不分配输出图，也不释放调用方的资源。

---

## 2. 库

每个平台只链接静态库或动态库中的一个。两者导出同一组 `mc_nscaler_*` 符号。头文件都是 `interface/mc_interface.h`。

| 平台 | 静态库 | 动态库 |
|------|--------|--------|
| iOS（arm64 真机，iOS 18.4+） | `lib/ios/libmagic_sr.a` | `lib/ios/libmagic_sr.dylib` |
| Android（arm64-v8a） | `lib/android/libmagic_sr.a` | `lib/android/libmagic_sr.so` |
| macOS Apple Silicon（macOS 14+） | `lib/mac_arm/libmagic_sr.a` | `lib/mac_arm/libmagic_sr.dylib` |
| Windows（x86-64） | `lib/windows/libmagic_sr.lib` | `lib/windows/libmagic_sr.dll` |
| Linux（x86-64，CPU 空域） | `lib/linux/libmagic_sr.a` | `lib/linux/libmagic_sr.so` |

Apple 静态库在 App 链接时还要带上系统框架：Foundation、Metal、QuartzCore、MetalFX、MetalKit、MetalPerformanceShaders。iOS 和 macOS 动态库已经链过这些框架。Android `.so` 已经链过 `liblog`、`libGLESv3`、`libEGL` 和 `libvulkan`。

iOS 与 macOS 动态库的安装名是 `@rpath/libmagic_sr.dylib`。iOS 嵌入步骤见 §8。

## 3. 快速开始（空域，Metal）

```c
#include "mc_interface.h"
#include <string.h>

static void *g_handle;

int sr_init(const char *model_path)
{
    ctrl_param_t ctrl;

    memset(&ctrl, 0, sizeof(ctrl));
    ctrl.input_type = INPUT_TEXTURE_RGB8Unorm;
    strncpy(ctrl.model_path, model_path, sizeof(ctrl.model_path) - 1);
    ctrl.scaler_factor = 2.0f;
    ctrl.alg_mode = SPATIAL_BALANCED_MODE;
    ctrl.backend = MAGIC_BACKEND_METAL;
    ctrl.log_level = MAGIC_LOG_ERROR;
    ctrl.spatial_sharpen_level = 0; /* 0..5 */
    ctrl.enable_msaa = 0;
    /* ctrl.gpu_context.device = MTLDevice*；NULL 表示系统默认设备 */

    g_handle = NULL;
    return mc_nscaler_control(&g_handle, MC_NSCALER_CMD_SET_PARAM, &ctrl, NULL);
}

int sr_process(void *in_tex, void *out_tex,
               unsigned in_w, unsigned in_h,
               unsigned out_w, unsigned out_h,
               uint32_t pixel_format)
{
    mc_nscaler_input_frame_t in;
    mc_nscaler_output_frame_t out;

    memset(&in, 0, sizeof(in));
    memset(&out, 0, sizeof(out));
    in.handle.pointer = in_tex;     /* MTLTexture* */
    in.format = pixel_format;       /* MTLPixelFormatRGBA8Unorm */
    in.width = in_w;
    in.height = in_h;
    out.handle.pointer = out_tex;
    out.format = pixel_format;
    out.width = out_w;
    out.height = out_h;
    return mc_nscaler_enable(&g_handle, &in, &out);
}

void sr_shutdown(void)
{
    mc_nscaler_disable(g_handle);
    g_handle = NULL;
}
```

其他后端调用相同。创建时选定的后端决定联合体里哪一个成员有效：

| 后端 | 彩色图句柄 | 说明 |
|------|------------|------|
| Metal、D3D11 | `handle.pointer` | `MTLTexture*` 或 `ID3D11Texture2D*` |
| Vulkan | `handle.vk_image` | 同时填写 `format` 和 `layout` |
| OpenGL / OpenGLES | `handle.gl_texture` | `GLuint`；`target` 为 0 表示 `GL_TEXTURE_2D` |
| x86 / NEON | `handle.pointer` | CPU 缓冲；`input_type` 为 `INPUT_BUFFER_R8` 或 `INPUT_BUFFER_RGB` |

第一次 `mc_nscaler_enable` 必须传入非 0 的 `width` 和 `height`，范围 `[64, 4032]`。之后传 `0, 0` 表示保持当前尺寸。输出宽高都非 0 时，必须等于由 `scaler_factor` 得到的尺寸（每一轴为 `floor(value * scale + 0.5)`）。

## 4. 生命周期

1. `*handle == NULL` 时，`SET_PARAM` 创建句柄。`model_path`、`gpu_context`、`backend`、`depth_reversed`、`depth_infinite`、`hdr_color` 在句柄存续期间固定。之后的 `SET_PARAM` 忽略这些字段的修改。
2. `mc_nscaler_enable` 读取输入并写入输出。两张图仍由调用方持有。
3. 尺寸和倍率不变时，重复 `enable` 会复用内部 GPU 资源。
4. `mc_nscaler_disable` 释放句柄。之后不能再使用该指针。
5. 用 `MC_NSCALER_CMD_QUERY_STATUS` 查询状态。`output_status_params_t.error_code` 为 `0` 表示成功。负的 `MC_ERROR_*` 定义在 `mc_interface.h`。

第一次带尺寸的 `enable` 之前，`SET_PARAM` 先按 640×360 占位，直到那次 `enable` 给出真实输入尺寸。

## 5. 倍率、模式与锐化

`ctrl_param_t.scaler_factor`

| 模式 | 范围 |
|------|------|
| 空域 | `[1, 8]` |
| 时域 | `(1, 8]`（1.0 会被拒绝） |
| x86 / NEON | 已实现的整数倍 |

`ctrl_param_t.alg_mode`

| 值 | 枚举 | 行为 |
|----|------|------|
| 0 | `SPATIAL_SPEED_MODE` | 空域，优先速度 |
| 1 | `SPATIAL_BALANCED_MODE` | 空域，兼顾画质和开销 |
| 2 | `TEMPORAL_SPEED_MODE` | 时域。见 §9。 |
| 3 | `TEMPORAL_BALANCED_MODE` | 时域。见 §9。 |

`spatial_sharpen_level` 是 `[0, 5]` 的整数。`0` 表示关闭。数值越大，锐化越强。

`enable_msaa` 独立。非 0 时，在所选超分路径之前多做一步预处理。

## 6. 纹理与尺寸

GPU 空域彩色输入用 `INPUT_TEXTURE_RGB8Unorm`（RGBA8）。`INPUT_TEXTURE_R8Unorm` 是单通道 GPU 路径。CPU 空域用 `INPUT_BUFFER_R8` 或 `INPUT_BUFFER_RGB`（平面顺序为 R、G、B）。

`magic_resource_t` 和帧结构里没有自动量出来的宽高。把宽高填在 `mc_nscaler_input_frame_t` 上。Vulkan 的 `format` 是 `VkFormat`。`layout` 为 0 表示未定义，时域校验会失败；`enable` 时要填这张图当时的真实 layout。

GL / GLES 不会自己把上下文设为当前。第一次 `enable` 时，调用线程上必须已经有当前上下文。

## 7. 模型文件

创建句柄的那次 `SET_PARAM` 之前，把 `ctrl_param_t.model_path` 设成可读 `.bin` 的绝对路径。路径最长 255 个字符再加 NUL。路径为空或文件打不开时返回 `MC_ERROR_INIT_MODEL_FILE_OPEN_FAILED`（`-100029`）或 `MC_ERROR_INIT_LOAD_PARAMS_FAILED`（`-100012`）。

当前合在一起的模型是 `model/magic_sr_gpu_params.bin`。空域模式和锐化级别在这个文件里选段。把这个文件的绝对路径传进去。库不会按工作目录搜索，也不会从环境变量读模型路径。

`tools/setup_models.sh` 只拷贝 `.bin`。拷完之后，App 仍然要把要加载的那个文件的绝对路径写进 `model_path`。

## 8. 动态库

### 8.1 iOS

`lib/ios/libmagic_sr.dylib` 是 arm64，最低 iOS 18.4，安装名 `@rpath/libmagic_sr.dylib`。这是真机库。

1. 把 dylib 加进 App target。
2. 在 **Frameworks, Libraries, and Embedded Content** 里选 **Embed & Sign**。文件会进入 `YourApp.app/Frameworks/` 并重新签名。
3. **Runpath Search Paths** 加上 `@executable_path/Frameworks`。
4. **Header Search Paths** 加上 `interface` 目录。
5. App 的 Deployment Target 设为 iOS 18.4 或更高，SDK 用 iphoneos。

动态库必须从 App 包内部加载。

### 8.2 Android

`lib/android/libmagic_sr.so` 是 arm64-v8a。放到 `jniLibs/arm64-v8a` 后用 `System.loadLibrary` 加载，或在原生链接行写上它的路径。App 把自己的 `.so` 和 MagicSR 编在一起时，用静态库 `lib/android/libmagic_sr.a`。

### 8.3 macOS Apple Silicon

`lib/mac_arm/libmagic_sr.dylib` 是 arm64，最低 macOS 14，安装名 `@rpath/libmagic_sr.dylib`。放进 App 的 `Frameworks`，Runpath 设为 `@executable_path/../Frameworks`。命令行工具可以用 `-rpath` 指向 `lib/mac_arm`。

### 8.4 Windows

`lib/windows/libmagic_sr.dll` 是 x86-64。链接导入库 `lib/windows/libmagic_sr.dll.lib`，并把 `libmagic_sr.dll` 放在可执行文件旁边（或放在 `PATH` 上）。静态库 `lib/windows/libmagic_sr.lib` 是把 MagicSR 直接链进程序时的另一种选择。

### 8.5 Linux

`lib/linux/libmagic_sr.so` 是 x86-64。这一份是 CPU 空域库。用 `-Llib/linux -lmagic_sr` 链接；若 `.so` 和可执行文件放在一起，rpath 用 `$ORIGIN`，也可以把 `.so` 的完整路径交给链接器。`dlopen` 只能从进程允许读取的路径加载。静态库是 `lib/linux/libmagic_sr.a`。

## 9. 时域超分

时域模式用彩色图、深度和运动向量累积历史。模式是 `TEMPORAL_SPEED_MODE` 和 `TEMPORAL_BALANCED_MODE`，句柄接口与空域相同。CPU 后端会以 `MC_ERROR_INIT_BACKEND_UNAVAILABLE` 拒绝时域。

用 `SET_PARAM` 创建。每次 `mc_nscaler_enable` 都要把 `in_frame.frame` 指到 `temporal_frame_t`，且 `struct_size` 为 `sizeof(temporal_frame_t)`。

| 字段 | 要求 |
|------|------|
| `depth`、`motion` | 输入分辨率上的 GPU 资源 |
| `jitter_offset_x/y` | 输入像素，原点在左上，+X 向右，+Y 向下 |
| `frame_index`、`reset_history` | 连续帧的序号应为上一帧加 1。切换场景或传送时把 `reset_history` 设为非 0，以丢掉历史 |
| `camera_near`、`camera_far`、`camera_fov_y` | 视图空间距离，以及弧度制垂直 FOV |
| `in_frame.command_buffer` | Vulkan：已经在记录的命令缓冲。Metal：NULL（库自己提交）或调用方的 `MTLCommandBuffer`。D3D11 / GL / GLES：NULL |

`motion_vector_scale_x/y` 为 `(0, 0)` 时，表示运动向量按输入宽高从 UV 换算。像素运动向量用 `(1, 1)`。`mv_jitter` 为 `0` 时，抖动只写在 `jitter_offset_*`。

深度是 `[0, 1]` 的 GPU 设备深度。反向 Z、无限远平面和 HDR 是 `ctrl_param_t` 上的创建期字段（`depth_reversed`、`depth_infinite`、`hdr_color`）。保持为 0 表示常规 Z、有限远平面和 LDR。

遮罩可选：显式的 `reactive` 或 `transparency` 纹理优先。未提供时，库会推导一个近似遮罩。这个近似值不是语义上的透明遮罩。

Vulkan 只往调用方的命令缓冲里记录，不负责提交。在 `mc_nscaler_disable` 或改变尺寸之前，要先等这批 GPU 工作结束。

```c
int temporal_vk_init(VkPhysicalDevice phys, VkDevice dev, const char *model)
{
    ctrl_param_t ctrl;

    memset(&ctrl, 0, sizeof(ctrl));
    ctrl.input_type = INPUT_TEXTURE_RGB8Unorm;
    strncpy(ctrl.model_path, model, sizeof(ctrl.model_path) - 1);
    ctrl.scaler_factor = 2.0f; /* (1, 8] */
    ctrl.alg_mode = TEMPORAL_SPEED_MODE;
    ctrl.backend = MAGIC_BACKEND_VULKAN;
    ctrl.log_level = MAGIC_LOG_ERROR;
    ctrl.gpu_context.physical_device = phys;
    ctrl.gpu_context.device = dev;
    g_handle = NULL;
    return mc_nscaler_control(&g_handle, MC_NSCALER_CMD_SET_PARAM, &ctrl, NULL);
}
```

按 §3 填 `mc_nscaler_input_frame_t` / `mc_nscaler_output_frame_t`，把 `in.frame` 指到时域描述，把 `in.command_buffer` 指到正在记录的缓冲，再调用 `mc_nscaler_enable`。

| 后端 | `gpu_context` | 命令缓冲 |
|------|---------------|----------|
| Metal | `device` 可以为 NULL | 可选 |
| Vulkan | `physical_device` 和 `device` 必填 | 必须是正在记录的缓冲 |
| D3D11 | `device` 必填；`device_context` 为 NULL 表示立即上下文 | NULL |
| OpenGL / GLES | 当前上下文 | NULL |

## 10. 常见问题

**Q：`SET_PARAM` 或 `enable` 返回负数？**
A：看 `output_status_params_t.error_code`，以及 `mc_interface.h` 里的 `MC_ERROR_*`。常见创建失败是模型路径（`-100029`、`-100012`）、尺寸超出 `[64, 4032]`（`-100002`、`-100003`）、倍率越界（`-100004`）、GPU 设备缺失（`-100025`）。

**Q：该链哪一个库？**
A：§2 里的一个文件。静态 `.a` / `.lib`，或对应的动态库。头文件始终是 `mc_interface.h`。

**Q：输出纹理谁分配？**
A：调用方。填在 `mc_nscaler_output_frame_t` 里。用创建它的图形 API 释放，并且要在 `mc_nscaler_disable` 之后，或等使用它的 GPU 工作结束之后。

**Q：可以同时有多个句柄吗？**
A：可以。每次 `SET_PARAM` 得到的 `void *` 都是独立句柄。

**Q：模型路径写在哪？**
A：创建用的那次 `SET_PARAM` 的 `ctrl_param_t.model_path`，填绝对路径。见 §7。

**Q：锐化做什么？**
A：`spatial_sharpen_level` 取 0 到 5。0 关闭锐化。数值越大，锐化越强。
